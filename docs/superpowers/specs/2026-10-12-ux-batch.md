## Root cause of the check-in bug (confirmed on prod 2026-10-12, read-only SQL)
`link_services` holds Fri 9 Oct with 255 checked in and Sun 11 Oct with 40, but `link_roster` has **0 rows** (W7 was never
built). The app names a checked-in person only through the roster, so the lists are empty. The same empty roster hides
every flow person from grade/quad logins (`personVisible` joins the roster).

## T1 Contract (src/core/link-contract.ts in YS; the console's copy/fixtures in 11.1)
`LINK_CONTRACT_VERSION` stays **1**. Every addition is **optional**, so an older peer still parses (row objects are
non-strict and strip unknown keys).
- `ClaimRequest.linkRev?: int >= 1` (console sends its rev). `ClaimResponse.linkRev?: int >= 1` (app sends its rev).
  Missing = 1. **Both sides set `LINK_REV = 2`** for this batch.
  - App: store the console's last `linkRev` with the heartbeat (`link_console`; a column via migration 0018, or inside an
    existing jsonb column if one exists). Admin Elvanto link page shows "Console out of date (rev N, app expects M):
    update and restart the console" when console rev < app rev.
  - Console: remember the app's rev from the claim reply. The Setup "YS link" row shows "YS app out of date (rev N):
    promote the latest build in Vercel" when app rev < console rev.
  - Console sends grade 6 (roster, flows) **only when the app's rev >= 2**; else sends `grade: null` for grade 6.
- `Grade` becomes `int 6..12 | null` (app side).
- `ServiceRow.checkedIn[]` item: `+ firstName?: string(<=60), lastName?: string(<=60)`.
- `GroupRow`: `+ history?: LastReport[]` (same object shape as `lastReport`), newest first, at most 8 (8 weeks back).
- `FlowRow`: `+ grade?: Grade, gender?: Gender | null, mobile?: string | null` (bare digits `04XXXXXXXX`),
  `mobileIsParent?: boolean` (true when the person has no own mobile and this is the parent's).

## Pinned app API shapes (Y1 implements exactly; Y2a/Y2b code against them)
- `GET /link/flows` rows add: `grade`, `gender`, `mobile` (decrypted, bare digits, or null), `mobileIsParent`,
  `assignedLeaderId` (uuid|null), `assignedLeaderName` (string|null). Step-0 rows are filtered **server-side** for
  non-admin/director. Scoping per T4 is server-side.
- `POST /link/flows/assign` body `{ flowId, personId, leaderId: uuid|null }` (null = unassign) -> `{ ok: true }`.
  404 if the module is not usable, 403 if the person is outside the login's scope, 400 if the leader id is unknown.
- `GET /link/lifegroups` groups add `history` (array, newest first, <= 8; same item shape as `lastReport`) and keep
  `grade`/`gender`; the server returns them already sorted per T8.
- `GET /link/checkin?serviceTime=`: response shape unchanged; checked-in people with no roster row are now included in
  the existing checked-in list using the pushed first/last name (Y1 decides the field placement inside the existing shape
  and documents it in the commit message; Y2a only needs them to render as named rows).
- `GET /link/admin/status` (or whatever the admin page's existing status read is) adds `consoleLinkRev` (int|null) and
  `appLinkRev` (int). The SPA shows the out-of-date line when `consoleLinkRev < appLinkRev`.
- Settings: `ministryConfig.modules.checkin | lifegroupReport | flows` each `'off'|'shadow'|'on'`, read via the existing
  `GET /settings`. SPA helper (owned by Y2b): `_linkOn(feature)` where feature is `'checkin'|'lifegroupReport'|'flows'`,
  plus `_linkAdminOn()` (admin login, always true). Y2a calls these; Y2b writes them (keep the old no-arg `_linkOn()`
  meaning "any link feature usable" so untouched call sites still work).
