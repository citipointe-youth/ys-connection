# Rework review R5: web/phone UI

Reviewer: R5 (web/phone UI). Branch `feat/oct-rework` @ 720a0bc. This was a read-only review. I did a static read of
`git diff master...feat/oct-rework -- public/index.html` and also ran the app locally (PERSISTENCE=memory, PORT=4310,
`npx tsx src/index.ts`).

I could not shrink the Chrome window below 1920 px, so I tested phone width another way. I loaded the SPA in a 360 px
`srcdoc` iframe inside the same origin, which makes real media queries apply at 360 px. This harness has a fine
pointer, so `@media(pointer:coarse)` rules did **not** apply there. I added that CSS back in by reading it.

Logins used: `admin` and `g79` (seed quad), both with demo1234. Steps: Simple logins on, then Prayers off, then Bus on,
then New person On. For layout, I injected fake All cars data into the page. That data was client-side only and was
never saved.

## Important

**I1. The Bus nav slot shows the admin-editable Bus label without esc(), and the label wraps on phones.**
`public/index.html:1916` returns `{ id:'bus', label:L('busMinistry') }`. `_initShell` (`:1326-1328`) then puts
`${it.label}` / `${it.mbl||it.label}` straight into both navs. `labels.busMinistry` is any string of up to 40 characters
(`src/core/ministry-config.ts:59`). The More sheet escapes the same label (`:1926 esc(m.label)`).
- Escaping scenario: an admin sets the Bus label to `<img src=x onerror=alert(1)>` (28 characters). Then they turn
  Prayers off, turn Bus on and leave New person off. The script runs in the nav of every login that has the Bus slot.
- Wrapping scenario (seen in the browser at 360 px): the default "Bus Ministry" wraps to two lines and the bottom bar
  grows to 76 px. That is exactly `.pg`'s 76 px bottom padding (`:143`), so any longer label would cover content.
- Fix: `label: esc(L('busMinistry'))` and add `mbl: 'Bus'`. Or escape `it.label` / `it.mbl` inside `_initShell`, but
  the mbl values are trusted HTML, so escape at the source instead.

**I2. Grade filter chips are about 30 px tall, under the 40 px target, and the phone CSS does not fix this.**
`.fc` (`:290`) uses `padding:6px 12px; font-size:12px`. Measured at 360 px: the 7/8/9 chips are 32×30, All is 40×30
and My grades is 83×30. The pointer:coarse block (`:519-522`) raises `.btn-sm, .tbbtn, .btn-icon` to 40 px but not
`.fc`. The `.vg-bar` that `_vgBar()` (`:1505-1519`) adds to six screens is the main control for Junior/Senior logins.
- Scenario: a leader on a phone taps "8" and hits "7" instead. The wrong grade toggles, and the change saves to the
  server 600 ms later.
- Fix: add `.vg-bar .fc{min-height:40px;min-width:40px}` to the pointer:coarse block. You could also add `.fc` there for
  all chip rows. The row still fits on one line at 360 px, because it currently measures about 300 px.

**I3. Picking "I am…" on Home leaves the grade bar stuck on "Pick who you are on Home".**
`chooseHomeLeader()` (`:2894-2899`) only calls `renderHomeFollowup()`. The Home `_vgBar()` (`:2711`) and the
grade-filtered "Attendance by Grade" tiles and birthdays are only redrawn by a full `render()`.
- Seen in the browser as g79 with Simple logins on: I picked "Emma Clarke" in the Home picker. The bar still showed
  three disabled chips and still said "Pick who you are on Home to filter by your grades". It only became live after a
  full render or a trip to another page.
- The hint also points upwards to a picker that is about 490 px *below* the bar.
- Fix: in `chooseHomeLeader`, and in the Home "Not you?" handler (`:2809`), call `render()` when `_vgActive()`.
  Reword the hint to "Choose your name below (I am…) to filter by your grades".

## Minor

**M1. The confirm shows Bus warnings even when Bus is off.**
`confirmSaveMinistrySetup` (`:6838-6842`) always adds "Quad logins stop coordinating Bus" and the red "No Bus
coordinators are set. Only admin and director can run Bus." It does not check `modules.busMinistry`.
- Seen: with Bus off, turning Junior/Senior logins on showed both lines, which is two irrelevant warnings.
- Fix: show both only when `draft.modules.busMinistry` is true.

**M2. Confirm wording.**
- "turns off ${n} grade logins" reads "turns off 0 grade logins" when the Grade role is already off.
- "Junior/Senior Girls/Guys" is slash-heavy.
- Suggested text: "This switches off the N grade logins (they come back if you turn this off) and renames the 4 quad
  logins to Junior Girls, Junior Guys, Senior Girls and Senior Guys." Leave out the count when n is 0.
- The success toast says only "Renamed 4 quad logins" (`:6576`). It does not mention the grade logins.

**M3. Locked controls explain themselves only through `title`, which phones never show.**
- The Simple preset button (`:6556`) and the Cohort model select (`:6565`) are disabled with
  `title="Turn off Junior/Senior logins first"`, so on a phone they are dead with no reason given.
- The Grade role row (`:6543`) does it right: it has a helpTip ("Off while Junior/Senior logins is on").
- Fix: add a one-line `help-text` under the presets and the select when `simpleOn`.

**M4. Help text wording (`:6546`).**
- "saved for the leader picked in I am" should be "…for the name chosen in "I am…"".
- "Needs the Complex cohort model and the Quad role" is fine.
- "Quad logins stop coordinating Bus, unless the leader picked is a Bus coordinator" is jargon for a youth pastor.
  Suggested: "Bus is then run by admin, director and named Bus coordinators."

**M5. All cars rider name overflows its row.**
At `:9009` the name is `<span class="li-title">`. `.li-title` relies on `white-space:nowrap; overflow:hidden;
text-overflow:ellipsis` (`:196`), which does nothing on an inline span.
- Seen at 360 px: "Maximilian Throckmorton-Wellington" overflowed its row by 89 px. It was cut off with no ellipsis and
  ran under the dropped-off tick. Page-level horizontal scroll did not happen, because `.pg` has `overflow-x:clip`.
- Fix: use `<div class="li-title">` / `<div class="li-sub">`, which is the pattern the rest of the app uses.

**M6. All cars uses the `.li` card style for rows that cannot be tapped.**
- `.li` has hover shadow and `:active` scale (`:182-183`), so the rows look tappable, and they are nested inside a
  `.card`, which gives a card-in-card look.
- The grade chip is hard-coded `Y9` (`:9010`) instead of the app's `_gradeWord()` / "Yr" wording.
- Fix: use plain flex rows with a `border-top`, and write the chip as `${esc(_gradeWord().slice(0,2))} 9` or "Yr 9".

**M7. The grade bar does not tell screen readers or the user which filter is on.**
- The other grade rows carry `role="group" aria-label="Filter by grade"` (e.g. `:3165`); `.vg-bar` does not.
- The chips have no `aria-pressed`.
- "My grades" never shows an "on" state, even when the filter equals the leader's own grades.
- With no "I am…" pick, the disabled chips use `fc on`, so they look selected and tappable.
- Fix: add `role="group" aria-label="Filter by grade"` and `aria-pressed`. Highlight "My grades" when the leader has
  no saved override. Show the disabled chips without `on` and with `opacity:.55`.

**M8. "Turn off" in the Prayers modal (`:6878-6884`) suggests the change is immediate.**
- It only changes the draft, and the admin still has to press Save Youth Setup.
- Suggested button text: "Turn off (then Save)", or add a line: "Press Save at the bottom to apply."

**M9. Plausible, not reproduced: the Youth Setup toggle rows are 22 px tall.**
- The checkbox is 13 px and the "?" helpTip is 18 px. This is the same pattern as the existing role and module rows,
  so it is not new to this branch.
- Fix if wanted: `.fg input[type=checkbox]{width:20px;height:20px}` and `label.fg{min-height:40px}` under
  pointer:coarse.

  and "N not on a car yet." It also renders correctly at desktop width.
