# Elvanto link app side: review RV5, web/phone UI (2026-10-12)

Branch `feat/elvanto-link-app` at `905d62e`. Read-only review. Screens: the door, the leader quick check-in sheet,
the lifegroup report, flow steps, the pill and banners, the New person host line, the Elvanto link admin page and log.
All line numbers are `public/index.html`.

## How it was checked

- **Static:** the whole `LINK CSS` block (726–793) and `LINK MODULE` (9069–10286), the New person host code
  (8888–8903, 9008–9033), `esc()` (1163), `modal()` / `_moFitViewport()` (1293–1311) and the shared button and sheet CSS.
- **Local run:** `PERSISTENCE=memory PORT=4335 LINK_SYNC_TOKEN=<throwaway> npx tsx src/index.ts` (no watch). The server
  was stopped afterwards and port 4335 was confirmed closed. A scratch script set the switch to Shadow and pushed a larger
  roster (45 students with long and apostrophe names, 20 leaders, 1 `other`), 2 services, 3 groups, 10 flow rows and
  the fixture claim. Fixtures in the repo were not changed.
- **Phone width: it was possible, with a workaround.** `resize_window` does not work here (`innerWidth` stays 1920),
  and the app's frame headers block an iframe of `/`. A **same-origin `srcdoc` iframe** works: fetch `/`, load the
  HTML into an iframe 360 × 740 px. X-Frame-Options applies only to network-loaded responses. Inside it,
  `innerWidth` = 360, `(min-width:768px)` is false, and the API calls and the session work. Page code was driven by
  injected `<script>` tags (the CSP blocks `eval`). Limits:
  - The iframe is `pointer:fine`, so the `(pointer:coarse)` 40 px rule for `.btn-sm` did not apply. Coarse heights
    below are worked out from the CSS.
  - A desktop scrollbar took 15 px, so the content was 345 px wide.
  - There is no on-screen keyboard, so the keyboard checks are static only.
  - Desktop was checked at 1280 px.
  - The Chrome tab was new and was closed at the end. There were no console errors.

## Findings

Counts: Critical 0 · Important 3 · Minor 13. Sides: app 15, both 1 (contract wording).

### Important

**I1. Admin Matching: the Match buttons are pushed out of the card and can't be reached on a phone.** side=app
- `public/index.html:780` (`.lk-kv span{…;flex:none}`) and `:10190–10191` (candidate row = `.lk-kv` with the
  "name · Yr · DOB" text in a `<span>` and the Match button beside it).
- **Scenario:** at 360 px, an unmatched person "Charlotte-Rose Montgomery-Fitzwilliam" has candidates. Measured: the
  card's right edge is at 329 px, the first candidate's span ends at 396 px, and its **Match button sits at 469 px**,
  clipped and invisible. The DOB is cut off ("… Yr 9 · 201"). The second candidate's Match ends at 351 px, half
  hidden. The person's header `Yr 9` also wraps to two lines.
- **Result:** an admin on a phone can't match a person with a long name. Matching is how check-ins reach YS
  attendance (the shadow check).
- **Fix:** give the candidate row its own class, or override inside it: `span{flex:1 1 auto;min-width:0}` so the
  text wraps, and keep the button `flex:none`. Better still, put name / Yr / DOB on one line and the Match button
  below on narrow screens. Don't change `.lk-kv` globally without checking the Status card, which relies on it.
- Other side needed: no.

**I2. Disabled primary buttons look exactly like enabled ones.** side=app (the gap is app-wide; the link screens depend on it)
- `:161` `.btn-primary` has no `:disabled` rule. The only disabled styles are `.btn-ghost` (`:167`) and a few
  module-specific ones.
- **Scenario (measured):** New report on a group whose last report has today's date opens with the clash warning,
  and Send is `disabled` with opacity 1, full accent colour and `cursor:pointer`. The same goes for **Submit (0)** in
  the leader sheet (`:9624`) and **Use this service** before a pick (`:9567`).
- **Result:** a leader taps Send or Submit (0) and nothing happens, with no visual cue. The V1 smoke reported
  "Submit (0) was disabled", which is true of the attribute but not of the look.
- **Fix:** add `.btn:disabled{opacity:.45;cursor:not-allowed;transform:none}` (or the same rule scoped to
  `.lk-*` / `.bus-sheet-actions`, if the app-wide change needs its own check). Other side needed: no.

**I3. The practice line tells leaders to "Check in the usual way" on the lifegroup report and flow step screens.** side=both
- `:9167` (banner for any shadow type) and `:9132` (`_lkStatusText` `shadowed`, used for report and step rows).
- **Scenario (seen):** in Shadow, Lifegroup report and Flow steps both show the grey banner "Practice mode: not sent
  to Elvanto. Check in the usual way." A sent report row shows the same line.
- **Result:** on the shadow Friday, a leader filling in a report is told to "check in". The right instruction is to
  do the report or step in Elvanto as usual, so they may skip doing it there, and practice reports never reach Elvanto.
- **Fix:** take the line from the screen's types: check-in types keep the contract text; report and step types
  read "Practice mode: not sent to Elvanto. Do it in Elvanto as usual." The status line is quoted "word for word"
  from contract §5.3 (`elvanto-link-contract.md:355`). That is a doc wording change, not a fixture or schema change,
  but the console team should agree it. Other side needed: yes (contract wording note only).

### Minor

**M1. The red "Not saved — tap to retry" pill is about 22 px tall.** app. `:727` (`.lk-pill` 12 px font, 4 px padding)
and `:9305`. It is the only manual retry. The 60 s auto-retry continues, so this is not Important. Fix:
`.lk-pill.bad{min-height:40px;padding:8px 14px}`.

**M2. Checkbox rows are about 20–24 px tall.** app. `:784–785` `.lk-chk`: "Group did not meet", "Keep notes
private", "Keep note private", and the first-timer "Check them in to …" tick on New person (`:10075`). Measured 20 px.
The label is tappable, but the row is short and sits next to other controls. Fix: `.lk-chk{min-height:40px}`.

**M3. The "Checked in · N" summary and the full-width secondary buttons are 39 px.** app. `:757` (10 px padding +
13 px text) and `.btn-full` secondaries such as New person and Check in leaders. They are 1 px under the target, so
this is cosmetic. Fix: `min-height:40px` on `.lk-done summary`.

**M4. "Back to the group" / "All groups" and "Tick all" are 29 px on desktop.** app. `btn-ghost btn-sm` at
`:9618` and `:9820`. On a touch phone the coarse rule lifts them to 40 px, so this is only a desktop / touch-laptop
note.

**M5. Activity date range: the second date input overflows the card at phone width.** app. `:10224–10225`. Two
`type=date` `.fi` sit in one `.lk-filters` flex row. Measured: the To date runs from 200 to 359 px against a 345 px
page, so it is clipped (there is no page scroll, because of `overflow-x:clip`). Chrome's date input has a minimum
width of about 159 px. On iOS it is narrower (Plausible OK there). Fix: `flex-wrap:wrap` on that row, or
`min-width:0;flex:1 1 140px` on its inputs.

**M6. The door screen puts the first name below the fold on a phone.** app. `:9468–9477`. At 360 × 740 in Shadow
with the console offline, there are three banners, the service card, New person, Check in leaders, search + grade
and the summary card. The first "Still to come" row starts at about y = 490 px, and the search box scrolls away
once you scroll the list. Fix (cheap): make `.lk-filters` on the door `position:sticky; top:<header height>` with a
background. Optionally put New person and Check in leaders side by side.

**M7. Check out still shows when the console reports `checkOut: locked`.** app. `:9520` hides it only for `off`.
In the fixture's normal state (`locked`) every checked-in row offers Check out, the banner says it isn't connected,
and the server refuses the tap. Fix: hide it, or disable it with the locked line, when `_lkCap('checkOut') === 'locked'`.

**M8. Admin Status / Today / Activity show raw codes.** app. `:10168` (`shadow`, `locked`, `live`), `:10176`
(`pending`, `claimed`, `unclear`), `:10140` and `:10146` (outcome `saved`, `replay`, `refused:LINK_ID_REUSED`) and
"Mirror: roster". Admin only, so readable, but not plain wording. Fix: a small label map (Practice / Not connected /
Live; Waiting / Sending / Not sure; Saved / Already sent / Refused).

**M9. The Export button uses the `upload` icon.** app. `:10229`. It downloads a file. Fix: use a download-style
icon, or no icon.

**M10. "Who are you?" sheet: no search, and Cancel is not sticky.** app. `:9683–9686`. It lists every active
leader A–Z (40+ at YS Brisbane) with Cancel at the very end (`btn-secondary btn-full`, so the app's sticky rule at
`:715` does not apply). It opens before every first report or step. Fix: wrap Cancel in `.bus-sheet-actions`, and
add a filter box when there are more than about 12 leaders.

**M11. The Complete sheet's buttons are not sticky and don't stretch.** app. `:9978` / `:9990`. The
`.bus-sheet-actions` is inside `<div id="lk-fs">`, so `.mo-box > .bus-sheet-actions` (`:718–719`) doesn't match.
Seen: Cancel and Complete are content-width, left-aligned. The sheet is short, so nothing is hidden today. Fix: render
the actions outside `#lk-fs`, as the leader sheet does.

**M12. New report opens straight into the "already a report" state.** app. `:9857` (date = `g.defaultDate`) and
`:9785`. Seen with the fixture group (thisWeek `reported`): New report → Date = the last report's date → yellow
warning, and Send is disabled but looks enabled (I2). "Edit it." is not a link. Fix: when `defaultDate` equals
`lastReport.date` and the report is editable, have New report open Edit, or put an "Edit the last report" button in
the warning.

**M13. Small wording and consistency items.** app.
- The logout guard says "N check-ins haven't been sent" but counts reports and flow steps too (`:9320`). Use
  "N actions" or the type.
- The door grade filter says "Grade 7" while the chip says "Yr 7" (`:9467` vs `:9511`). It is also fixed at 7–12, so
  a Grade 6 ministry can't filter Grade 6.
- Group names show the full "Brisbane - YS - …" prefix (`:9745`). The app's `lgDisplayName()` strips it elsewhere.
- The flow rows that can be completed have no visible affordance (no chevron or button) (`:9965`).
- The ticked box shows the circle-check icon inside a filled square (`:9615`, `:9796`), which looks doubled. A plain
  tick path would read better.
- "Completing may send this step's message." (`:9989`): consider "Completing may send Elvanto's email or text for
  this step."

### Plausible (not proven)

- **New person host line race** (`:8892–8895`). `_nyHost()` needs `LINK.ldrs` (from `/leaders`) to name a picked
  "I am". If Send is tapped before that fetch returns, the host is empty and the "Who are you?" picker opens even
  though a leader is already picked. The picker then shows the same list, so this is harmless but confusing. For a
  junior `leader`, the fallback is `S.user.displayName` (the account name), not the leader's name.
- **Keyboard over search:** the door search box sits about 360–400 px from the top at 740 px height. With an iOS
  keyboard of about 300 px, the field stays visible (the browser also scrolls a focused field into view), but the
  filtered rows under it are behind the keyboard. Not tested on a device.
- **Two people with the same name and grade** look identical at the door (name + grade only, by design). Seen in the
  test data. Worth an owner decision if it happens at YS.

## V1 smoke minors (ranked from the UI seat)

1. **Pushes apply while the switch is Off:** Minor, by design. `sync.service.ts:38` only sets claim `max` to 0 when
   Off, so the mirror stays fresh for the moment the switch goes back on. Recommend a code comment and a line in the
   admin Status card.
2. **Log rows for replays have no target:** Minor. `link.service.ts:229–234` returns `ok(prev,'replay')` before the
   target is resolved, and `doEnqueue` (`:358–363`) logs `tgt` as is. The Activity list then shows the row with no
   target name (`:10137`), so an admin can't see who it was for. Fix: fill `tgt` from `prev.payload` on replay.
3. **"resolved" keeps the old "unclear" detail on a sent row:** Minor. The admin Status card only lists `unclear`
   rows (`:10173`), so the UI doesn't show the stale detail. It affects API readers only. Not re-checked in the repo
   code by RV5.
4. **The server accepts a check-in for a roster "other" person:** Minor. The door never shows `other` people, so the
   UI can't send one. Only a hand-made request can. Not re-checked in the code by RV5.

## Verified OK

- **esc():** every user or server value in the link module's HTML goes through `esc()` (names, meets, flow and step
  names, status `message`, log login and device, roster names, candidate names, DOB, error texts, banner text). The
  `onclick` arguments use `esc()` inside single-quoted JS strings, so `&#39;` would decode back to `'`. That is safe
  here only because every id passed is a lower-case UUID enforced by the contract Zod (`link-contract.ts:25`, `:43–101`)
  or an app UUID. Names are never passed in an `onclick`. Apostrophe names ("D'Angelo", "O'Brien") rendered correctly.
- **No dark mode:** there is no `prefers-color-scheme` anywhere in `public/index.html`.
- **SVG icons only:** all icons are `icS()` (check, info, plus, edit, arrl, arrr, chevd, upload). The only non-ASCII
  characters in the module are punctuation (· – — …), which the app already uses everywhere. There are no symbol
  glyphs.
- **No horizontal page scroll at 360 px** on the door, the leader sheet, Lifegroup report (list, group, form), Flow
  steps or the Complete sheet (scrollWidth = clientWidth). The admin page has no page scroll either, but it clips
  (I1, M5).
- **Sticky Submit never hides the last row:** the leader sheet with 43 leaders, one with a 3-line name. Scrolled to
  the end, the last row ends at 669 px and the Submit bar starts at 681 px. The Pick a service sheet is the same
  pattern. The bar goes static while a field is focused (`:722–723`).
- **Tap targets that pass:** door rows (whole row tappable, about 47–57 px), leader sheet rows 43 px (whole row),
  member tick rows 43 px, `.lk-opt` 44 px, flow rows above 40 px, and every `.btn-sm` on touch through
  `(pointer:coarse){min-height:40px}` (`:519–521`).
- **Plain wording:** the leader lines match the contract. "Waiting to send." and "In Elvanto." read well. The pill,
  the "Not linked" chip and the "Elvanto will show: Self identified leader: <name>" line are clear.
- **Desktop at 1280 px:** the door, the admin page and the matching card (I1 doesn't happen at desktop width) lay out
  in the 1000 px `.pg` column with no overflow.
- **Behaviour while running:** a tap ticks the row at once with "Waiting for the console.". The pill shows "All
  saved" and fades. A repaint keeps the scroll position and the `<details>` open state. The leader sheet's Tick all
  becomes Untick all, and the count follows. No console errors.
