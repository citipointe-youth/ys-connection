# Elvanto link contract revisions (LINK_REV)

Lifted from the root CLAUDE.md Release process (2026-10-30). Each entry describes current contract behaviour; newest first. Older revs (7-11): `docs/history/claude-md-archive.md` and `docs/HISTORY.md`.

- **Link contract order** (`LINK_REV`, `core/link-contract.ts`; the other side is Project 11.1, the Elvanto Sync Console). Each rev adds optional capability keys; capabilities are `Partial`, so an older console that lists no key is never leased that type (a missing type means off). The console sends the new keys only after the app's claim reply says its `linkRev` is high enough. **ROLLOUT ORDER:** app promote first, then merge + restart the console (the first roster build takes minutes; keep it outside the service window). **X-1 (2026-10-19):** the claim refuses a console below `MIN_CONSOLE_REV` (12; missing `linkRev` = 1) with 409 `LINK_CONTRACT_MISMATCH` before the heartbeat, and no field is gated on a rev any more; a future rev bumps `LINK_REV` and raises `MIN_CONSOLE_REV` only once every console runs it. A migration a new console rev depends on ships with the app first: migration 0033: It must be applied (the promoted build) BEFORE the rev 8 console answers an Other lookup. `DEPLOY.md`: ship YS before the 11.1 console.

Rollback: a rev-21 console against a rolled-back rev-20 app works (no `offered`, boolean path); expect the admin banner "Console out of date (rev 20, app expects 21)" between the two ships. **Y7 lease note:** a claim with `max <= 0` (the console's heartbeat `beat()`) now renews this console's own live (`lease_until >= now()`) `claimed` rows to `greatest(lease_until, now() + leaseSeconds)`; `attempts` is never touched, a lapsed lease is not revived, another console's rows are untouched (stops long consent batches re-handing rows and inflating `attempts`; works for rev-20 consoles too, no rev dependency).
