# Bus Ministry


Naming: the Bus tab's UI label is **My car** (internal id `mycar`); "Trip logging" below and in code comments (`BUS-1`) means that same tab.
Drop-home car runs after the service night. Spec: `docs/superpowers/specs/2026-10-05-bus-ministry-design.md`; plans `…-bus-ministry-r1-core.md`, `…-bus-ministry-r2-r3-google-analysis.md`; past nights `docs/superpowers/specs/2026-10-09-bus-past-history.md`.
- **Visible to every login since 2026-10-09** (owner decision; `visibility`/`regionCode` settings removed, address search always `au`). `ctxOf` rejects a `?now=` >36 h from the server clock. First real use Fri 2026-10-09.

#### Owner rules (decided 2026-10-06 — not bugs)
- Gender = strong soft preference (cost), **except** hard rule (replaced the old lone-girl rule 2026-10-06): a non-fixed **girl may only be placed in a car with ≥1 female leader** — `buildFleetProblem` sets her `allowedVehicles` to the female-eligible cars. None eligible → Unassigned, counted as `noFemaleLeader`. **Google reads an empty `allowedVehicleIndices` as "any vehicle"**, so `GoogleRoutingProvider.solve` drops stops with `allowedVehicles: []` from the request and reports them skipped — don't remove that. Hand-placed → run view `needsFemaleLeader` → "No female leader" chip only.
- Pool auto-fill skips cars that **end at an address** (driver goes home; a pool leader would be stranded). Exception: a charter bus (below).
- **Charter bus (BUS-2, 2026-10-18, operator Session 2; migration 0038):** a fleet vehicle with `kind:'bus'` (Car setup "Charter bus" box; `bus_vehicles.kind` + per-night copy `bus_run_vehicles.kind`, absent = car). Its drop-off = its **Ends at → Address** (required for a bus; the tonight-only ends override re-snaps every bus rider). Drop-off after only; pickups stay cars. A rider's choice = a `bus_addresses` row with `vehicle_id` (label `Bus drop off`), **remembered** as their last-used address: next week the picker pre-selects `Bus drop off: <address>`; `busPatch` seats them on the bus while it runs, else at their latest home address (none → add refused / no pin). The bus is a **fixed car** (`fixedCarIdsOf`): left out of Generate / Fit in / the Google solve (nothing new sent to Google), `reorderCar` no-op, no Optimise, one Maps stop; the pool still fills it (`autoFillPool` `bus: true` bypasses the ends-at-address skip). Never "full": over capacity keeps everyone and shows **Over by N**. **No gender / female-leader rule** on a bus. **Unassign all / Undo leave bus riders** (take one off by Move or Edit address). `syncBusRiders` re-applies choices on bus on/off, ends change, kind change and at Generate start; it skips own-car riders and dropped riders (an own car never pulls/loses a rider to the bus; the own-car/trip pickers never offer the bus). **Car → bus mid-night** sends its home-address (door) riders to Unassigned. History `ride.car` = `"<name> (bus)"`. Trip nights (bare runs) have no fleet copy, so no bus there: a bus row falls back to home. The SPA sends `kind` on every vehicle POST/PATCH (test `every PATCH of an existing bus carries kind`); since review M2 a save **without** `kind` keeps the prior row's kind (`v.kind ?? prior?.kind ?? 'car'`, the bus drop-off check runs on the resolved kind), so an old cached SPA can't demote a bus. Review fixes: `syncBusRiders` also leaves **locked** cars alone (L1); a full/over-full bus still gets a pool leader (L2, `autoFillPool` skips the seats check for a bus); a run-vehicle PATCH can't clear a bus drop-off (`endsPlaceId: null` refused, L6). `BusRiderView.noHome` = on a bus with no home address saved; the bus turn-off confirm names them. Adding/editing a student onto an over-full bus toasts "<bus> is over by N". Car setup totals count a bus as never short (seats = max(seats, riders)) and say "1 bus + 1 car". Bus cards on Assign have no stop numbers or pin icon. Ticking "Charter bus" sets Ends at → Address and focuses the address. The picker's bus row reads `Bus drop off · street · suburb` (same format as saved rows). One no-home message: "Add a home address first: tap their name on Students". Move off a bus with no home address (to Unassigned or any car, incl. an own car) keeps the row with **no address** (no pin, `addressId` null), never the bus drop-off (R19-L5/K1).
- Address picks: any suggestion (exact address **or street**, `includedPrimaryTypes` street_address/premise/subpremise/route) is required for a new address — typed text without a pick is rejected (400 "Pick the address from the suggestions list"). Exception: Trip logging riders/end address are optional (below). A street placeId Route Optimization can't locate ("No LatLng location for placeId") is resolved once via Place Details to the street midpoint and resent as lat/lng (request-scoped, never stored); if that fails → 422 `ROUTING_BAD_ADDRESS` naming the rider/car/church. Blank label defaults to the street part ("3 Lindsay Court"); search hits carry `street` for old unlabeled rows.
- Removing a rider who is an **unlinked guest with no other run rows** deletes the guest + saved addresses. Students are never deleted from Bus.
- Trip logging "I am" picker = `onCarLeaders` (leaders on a running car this week, unscoped by the login's grade/quad).
- Parent consent = the Elvanto bus consent form (spec 2026-10-22). Chip per calendar year (site zone), details for roster logins and coordinators only, warning only, never blocks. `bus_consents` dropped in 0044.
- Moving someone to **Unassigned unpins them** (Generate/Fit in place them again). Move sheet has **Unpin** (`{ unpin: true }`).
- **Preferred grades were removed 2026-10-20** (operator, B1): no grade choices on the vehicle or Leader pool sheets, and the solver ignores `prefGrades` (gender is the only soft cost). The `pref_grades` columns, mapper and API fields are kept (accepted, stored, unused) so an old cached SPA never gets a 400; config `prefWeightMin` is unused.
- **Finish sooner counts:** `globalDurationCostPerHour = COST_PER_HOUR` (1 min of makespan = 1 min of driving), so "Try +N cars" / Generate split riders when it ends the night earlier.

#### Reference
- **Code:** `bus.service.ts` (all rules + RBAC via `bus:*`), pure `bus-logic.ts` / `bus-plan.ts` (`autoFillPool`, `buildFleetProblem`, `placementsFrom`), `IBusRepository` (in-memory + Supabase; encryption only in `supabase.bus.ts`), `/bus/*` routes, SPA block `/* ── BUS MODULE ── */` + `BUS MODULE CSS`. Every `/bus` call carries `?now=YYYY-MM-DDTHH:mm` (+ `&as=<leaderId>`). Module off → the Bus routes refuse (no per-role visibility setting; every login sees Bus).
- **Routing:** `src/services/routing/` — `GoogleRoutingProvider` (plain `fetch`, service-account JWT via `node:crypto`; Route Optimization needs `maxDuration` alongside `quadraticSoftMaxDuration` — we send the 12 h horizon) and `FakeRoutingProvider` (straight-line, SVG map). Fake when any Google env var is missing or `PERSISTENCE=memory`; `BUS_ROUTING=google` to test a real key in memory mode. Google gets place IDs + numbers only (tested via an allow-list of request keys in `routing.google-requests.test.ts` — add new fields there).
- **Env (server only):** `GOOGLE_MAPS_API_KEY` (Places API (New), Routes API, Maps Static API), `GOOGLE_SA_EMAIL`, `GOOGLE_SA_PRIVATE_KEY` (any paste form: PEM, `\n`-escaped, whole JSON, bare body), `GOOGLE_PROJECT_ID` (Route Optimization; SA needs Route Optimization Editor). A failed key logs its *shape* only. The Vercel MCP can't write prod env vars (403) — owner edits them in the dashboard, then redeploy + promote.
- **Generate:** one 30 s solve budget (`GENERATE_SOLVE_BUDGET_MS`) for the single solve; lock `LOCK_MS` 55 s (Vercel `maxDuration` 60 s; SPA waits 55 s); `lock_by` = `"<name>#<token>"` per call, shown via `lockName()`. `placed` counts saved rows. Roster writes (add/update/remove rider, own car save/remove) and Move/car setup respect the lock. Undo snapshot 2 min. Pool auto-fill never adds a leader that would push out a car's fixed riders.
- **Data:** no coordinates or drive times stored — only place IDs (encrypted). Guests purged after 28 days.
- **Permission split (2026-10-15, operator):** every Bus login gets **Car setup** and **Assign** tabs. Car setup writes (`saveVehicle`, `updateRunVehicle`, `setPool`, `setLeaderPrefs`) are `bus:use`; removing ANOTHER leader's own car is `DELETE /bus/run/own-car?owner=<ownerLeaderId>` (with the caller's own `as=`) and needs `bus:coordinate`. Route edits on Assign (Generate/Fit in, Move/Unpin, Unassign all, Undo) stay `bus:coordinate`; non-coordinators see Assign read-only (`_busRoutesHtml` `ro`, `_busRoutesHead` hidden). Any Bus login can mark a drop-off on any car. Route analysis (`analysis`, `analysisMap`, `extraCars`) = `gateAnalysisView`: every Bus login except a junior `leader` that isn't a coordinator ("My car only": riders redacted to name + suburb, but `leaders` + `fleet` are returned so Car setup works). Past button stays director/admin (`seesPast`). The no-church hint says "Set the church address in Bus settings" only to admin (only admin has that button); others get "Ask an admin to set the church address". SW `ysc-v108`; no migration.
- **My-car-only leader writes (r19, 2026-10-19):** a junior `leader` login (not a coordinator) cannot change a run car's leaders (`PATCH /bus/run/vehicles/:id` with `leaderIds` = 403; SY-03: joining a fleet car would open its riders' addresses and phones). Its own-car save takes only riders already in its own car or its connected students (`riderIds`, `newRiders.studentId`; anything else 403 before a rider/guest is created; walk-in guests stay addable; SY-04). SY-05 (past bus nights read-only via `?date=` without `bus:analysis`) was REVERTED by operator ruling: past-night trips stay open.
- **`search` is gated `bus:use`**; actors without `bus:roster` (the junior `leader`) only get their own connected students, street info stripped. Your car sheet: the draft lives in `BUS.ocDraft`, NOT `BUS.myCar` (background refreshes replace `BUS.myCar`).
- `snap_address` NOT NULL: Supabase stores a one-space sentinel for empty (`encSnapAddress`).
- **Trip logging (BUS-1, 2026-10-18, operator Session 2):** the My car tab (labelled "Trip logging" 18 Oct, back to **My car** 2026-10-19 per operator; code/docs still say "Trip logging") is LAST (Students · Car setup · Assign · My car; internal tab id stays `mycar`). Bus lands on **Students** (roster logins) / **Car setup** (junior `leader`). A trip = the leader's own car in that date's run: `?date=YYYY-MM-DD` on my-car / own-car / stops / optimise / dropped (`BusCtx.tripDate` → `tripRun`); window **today−14 … today+7** (local day, 06:00 cutoff), a later bus night is refused ("log it on the night"); a non-service date is a **bare run** (no fleet copy); viewing (`GET my-car`) never creates a run. `ensureRun` carries over from the latest earlier run WITH a fleet car, so a midweek trip never empties next Friday. Own-car rider and end address are **optional** (no rider address = `address_id null` + sentinel snap; an unpicked end address is saved as Last drop and the SPA toasts "No address picked — ends at last drop"); Students-tab add/edit still require one. Day picker under "I am" defaults to today. "I am" change = `_busIdentityChanged` (no `location.reload()`, `yap_bus_reload` gone). History `nights[].trip` (weekday ≠ service day) → Past "Trip" chip, export Nights/Rides **Type** column (Trip / Bus night); Nights/Avg/chart/regular count bus nights only. Trip kind (drop-home vs pickup) is not stored: a pickup = Ends at Church. No migration. Removing a trip on a non-service date (`removeOwnCar`) deletes its riders too (no 0-car night in Past); on a bus night they still go to Unassigned. On the Trip logging tab the header shows the trip's day (`_busHeadDate`). **Never silently moved (review B, 2026-10-18):** `saveOwnCar` never takes a rider out of another car/bus on that night (incl. past service nights in the window): they are skipped and returned as `skipped: [{name, car}]`, and the SPA toasts "<names>: already in <car> — move them in Assign". `ownCarDraft.riderIds` pre-ticks only remembered riders with no `runVehicleId`. Removing the last trip on a non-service date also deletes that run's not-riding rows (no empty date in Past). Past: trip rows/details never show "not logged" (no drop-off ticking on a trip); the stats strip is hidden when there are no bus nights. Trip logging shows a missing address as a neutral grey chip; a redacted (junior) view shows no address chip at all. A leader on a running car tonight sees "You're driving <car> tonight — open ›" on Car setup (opens Trip logging on the bus night). "All cars (N) ›" is a Past-riders-style row. **Poll (R19-L3, rel20):** `GET /bus/run/version?date=` returns that date's run `{runId, version}` (`{runId:null, version:0}` when it has no run; polling never creates one); on Trip logging for a day that is not the bus night, `_busPollTick` sends `?date=` and compares against `BUS.tripVersion` (learnt on the first tick), never tonight's `BUS.version`, so it refreshes only when that trip changes (test `rel20-l3-e2e.test.ts`).
- all times shown are labelled **drive time** (no per-stop dwell, owner decision). **Bus Lock** (0034): per car per night, coordinators only; Generate / Fit in / Try +N / pool auto-fill / Unassign all / Undo skip a locked car; manual moves still work.

- **Bus Lock (0034, `bus_run_vehicles.locked`):** fleet cars only; `fixedCarIdsOf` (own + locked cars) used by prepareFleet, undo, unassignAll: Generate, Fit in, Try +N cars and pool auto-fill skip a locked car; Undo neither pulls from nor puts into one. PATCH with `locked` needs `bus:coordinate` (403 otherwise); car off clears the lock; every car locked -> 400 "Every car is locked...".
