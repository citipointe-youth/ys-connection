# Error log and reconciliation

- **Error log** (Admin tab, `services.errorLog.record`): never throws; stores code, route, status, role, tier, fold key and the line-1 text only: never names, phones or values. Texts and tiers per code live in `src/services/error-log-text.ts` (`textFor`, computed at read time); same-cause errors fold into one row for 30 min (`fold_key`). **Self-clearing (auto-settle, 2026-10-24):** link `unclear` / `lease-lost` rows are live counts from the open outbox rows (not windowed writes); link refusals expire after 7 days or, **only for a type-wide reason** (`SUCCESS_CLEARS`: locked, too-old, service-not-offered, console-busy, lease-lost), on a later success of the same type; per-person/per-item refusals (person-unknown, form-unknown, not-landed, member-left, unknown, and `no-room`, dropped from the set by a later operator ruling on link seam review #3 because the console's no-room is nearly always about one person, ...) stay until the 7-day expiry or an admin Delete/Ignore (operator ruling A, ultra-review #4, 2026-10-24) (fixed-code count rows never expire this way); the sweep runs on each link result, at most every 10 min on claim, and on the admin Error log view. **`fix-no-field` (2026-10-24, `fyi`):** a consentFix refused `unknown` whose detail names a missing consent date field (derived from detail in `sync.service` `result()`, not a contract reason). **Client whitelist:** the report route must be in the router table (`errorLog.setKnownRoutes()`), otherwise it is stored as `page`.

**From the 2026-10-17 / 10-24 rounds (full text in `docs/history/claude-md-archive.md`):**
- Tiers now / later / fyi (Act now, Act later, FYI); two lines per entry from `textFor()`; FYI collapsed; Clear FYI = `DELETE /admin/errors?tier=fyi`.
- `record(r, setCount?)`: no setCount folds by `fold_key` (link `link|code|route`, else `code|status`) within 30 min; setCount keeps the fixed id; `setCount 0` deletes. `pending-24h` clears itself when nothing waits.
- **Reconciliation** (`src/services/reconcile.service.ts`, migration 0036 `reconcile_runs`): compares the Elvanto roster (`link_roster`), check-ins and lifegroup CSV data after each import. Report only: never writes to Elvanto; writes only roster matching (`rematchRoster`), its own `error_log` rows (category `reconcile`, setCount, ids only, never names) and `reconcile_runs`. Leaders excluded. Bounded to 10 s, never throws, never fails an import. Hook: `afterImport(kind)` in `container.ts` (called by `import.service`) runs `reconcile.run()` after a lifegroup import and `reconcile.rematch()` otherwise. No thresholds: count > 0 raises the entry, 0 deletes it (`record(r, 0)`).
- Endpoints: `POST /sync/reconcile/latest` (console sync auth, additive) returns the latest run for the Friday/Tuesday email (`reconcile` rows kept at any age); `GET /admin/reconcile/latest` (`admin:manage`) is the admin "Who?" view and the only place names are resolved (at read time). `POST /admin/reconcile/resend`: see `docs/areas/link-contract-revs.md` (r21 L6b).
- Auto-settle (2026-10-24): same-name import rows split by DOB (a row with no DOB still merges and counts as a collision); students-missing excludes no-grade students; consentFix refusals log `fix-no-date` / `fix-no-total`.
