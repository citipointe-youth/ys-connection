# Elvanto link (app half)

Contract revisions + rollout order: `docs/areas/link-contract-revs.md`. Consent hub, DNC, flows: `docs/areas/consent-flows.md`. Error log: `docs/areas/error-log-reconcile.md`.

The app half of the Elvanto link. The other half is Project 11.1, the Elvanto Sync Console on the office PC, which talks to Elvanto; this app never does. Contract: `docs/superpowers/specs/2026-10-11-elvanto-link-contract.md`; app spec `docs/superpowers/specs/2026-10-12-elvanto-link-app-design.md`. Set or rotate `LINK_SYNC_TOKEN`: see Release process.

**Architecture**
- **Phone → app:** a tap goes into a per-login queue in localStorage (`ysc.lkq.<user id>`, try/catch, memory-only after a storage error) and is flushed in batches of up to 50 to `POST /link/batch` (right away, on `online`, on `visibilitychange`, on the next tap). Every item has a client UUID, so a retry is a `replay`. There are no single write routes any more (T-42). The SPA block is `/* ── LINK MODULE ── */` in `public/index.html` (`_lk*`, state `LINK`): door check-in (`link-checkin`), leader quick check-in, lifegroup reports (`link-groups`), flow steps (`link-flows`), the admin page (`link-admin`), and the first-timer tick on New person.
- **App → Elvanto:** the console polls `POST /sync/claim` (heartbeat + lease of pending outbox rows), reports `POST /sync/result`, and pushes mirrors (`roster`, `services`, `groups`, `flows`) with `POST /sync/push/:kind`. `link.service.ts` (leaders/admin), `sync.service.ts` (console), pure `link-rules.ts` (service day, dedupe, outbox state machine, auto-match, effective check state), `core/link-contract.ts` (Zod, frozen fixtures in `src/tests/fixtures/elvanto-link/`, LF-only via `.gitattributes`), `ILinkRepository` (in-memory + `supabase.link.ts`).
- **Data:** migration `0017` = 8 tables `link_outbox`, `link_roster`, `link_services`, `link_groups`, `link_flow_people`, `link_console`, `link_mirror_state`, `link_log`. Notes in `link_outbox.note` are encrypted with `FIELD_ENCRYPTION_KEY` (AAD `link_outbox.note:<id>`). `link_log` is the identity + action log (admin view and xlsx export). The claim note (X1, `claimNote`): flow notes (completeStep, removeFromFlowStep) carry `<name>: "<note>"`, or the name alone with no note (2026-10-24); report notes keep `Self identified leader: <name> — <note>`.
- **Rules worth knowing:** "I am" (the self-identified leader) is required for reports and flow steps; a check-in tap older than 3 days is refused (`LINK_TOO_OLD`, counted from the tap); a late item changed by someone else after the tap is `LINK_STALE`; rate limit 600 new rows per 10 min per login; dedupe by (person, service, type).
- **The switch:** since 2026-10-12 each screen has its own switch (`modules.newYouthForms`, `checkin`, `lifegroupReport`, `flows`; Off / Admin only / On; see "Rules worth knowing" below); there is no `modules.elvantoLink`. Off is the stop button for that screen: `/link/*` answers 404 and the claim leases nothing, but mirrors still arrive. To stop all data flow, also turn off the link on the console. There is no practice/shadow stage for link writers (operator ruling 2026-10-15): every action type is live, and the app shows no practice banner.
- **Routes:** the house checklist applies: `/link` and `/sync` are in `router.ts`, the `vercel.json` regex and `sw.js` `API_RE`. The `/sync` routes are `sync: true` in the route table (no session; the adapter checks the token, exact and timing-safe, never logged).

**Rules worth knowing**
- **Modules per feature:** `modules.newYouthForms` (New person), `checkin`, `lifegroupReport`, `flows`, each off | admin | on (legacy `shadow` = `admin`). A stored config without the new keys inherits `newYouthForms`. Bus "All cars" follows the Bus module only. `gate(actor, features)` in `link.service.ts`: `/link/checkin` = checkin OR lifegroupReport; `/link/lifegroups` = lifegroupReport; flows + assign = flows; each batch item is refused `MODULE_DISABLED` when its own screen is off; the claim leases nothing only when all three are off. SPA: `_linkOn(feature)`, `_linkAdminOn()`; the no-arg `_linkOn()` = any usable. `renderLink` guards per page.
- **`link:admin` is admin only**, whatever the module states (oversight logins see only their own rows in `/link/actions`, cannot cancel others'). Admin therefore always has a More entry.
- **Step 0 = `stepOrder <= 1`** (the console numbers every Elvanto step from 1, empty ones included): since 2026-10-14b hidden from **non-admin** logins by default (admin/oversight never; `stepHidden(actor,row,picks)`) (per flow: Youth Setup → Modules, `modules.flowHiddenStep`) (it is the 7-day wait, moved on its own after contact consent or 6.5 days; the Form Approve & Consent screen is its one view), filtered server-side and refused (403) on complete/assign.
- **Grade 6:** junior (quads g79/b79, `computeQuad` 6..9) and the Simple-logins Grade 6 lock is gone. One entry rule, `assertGradesInRange(structure, grades)` in `ministry-config.ts` (uses `gradeRange`): grade 6 is accepted only when Include Grade 6 is on, in student/account/leader create + update, `PATCH /leaders/:id/grades` and New person (Elvanto option `807c9c80-3825-11e1-9229-ea942707ad51`). Zod floors widened 7 -> 6; the range check enforces. T14b: ONE junior bracket, `quadGradesOf(quad, structure)` (access-control.ts): 6-9 when `gradeMin` is 6, else 7-9; `canAccessGrade`, lifegroup-stats grades and the client `quadGrades`/`_juniorMin` all follow it. Server quad labels via `quadLabelFor(quad, false, gradeMin)` read 'Yr 6-9' when on. Service-attendance rows accept grade 6. Tests: grade6-quad.test.ts.
- **Check-out / Undo over a mid-send check-in (M2, operator ruling 2026-10-24, ultra check-in review):** when the person's open check-in is `claimed` (the console is sending it), a `checkOut` (or an Undo, which becomes one) is inserted and answers `saved` (pending) instead of "Still sending"; the claim already holds a checkOut behind an older pending/claimed checkIn of that person and service (`supabase.link.ts` claim, in-memory `blocked`). An `unclear` check-in, and a check-in over a claimed check-out, still refuse "Still sending". A pending check-in is still cancelled, not queued. If the console answers `retry` on that check-in (it goes back to pending), `/sync/result` cancels both the check-in and the queued check-out, so the Undo wins as before M2 (link seam review #1).
- **Check-out for no-roster people:** `checkOut` is accepted for a personId in that service's pushed `checkedIn` list even with no roster row; `checkIn` for them stays refused.
- **Edit of an older week's report:** `editReport` finds its base by `reportId` in [overlay last, mirror lastReport, history]; the submit window is for submit only. **2026-10-21 (T3):** a new report may be up to 8 weeks back (`REPORT_SUBMIT_DAYS` 56 in `link.service.ts`, `-56` in the SPA's `_lkReportDateFor` / `_lkFormHtml` / send check): an app rule only, the console has no limit; the shown-back refusals (`lastRefused`) use the same window. History holds only the 8 newest reports, so a group with more than 8 in 8 weeks can show an old week empty (the console still refuses `report-exists`). Services older than 7 days are not pushed, so an older report picks No service.
- **2026-10-21 (L6a, no LINK_REV change):** a refused check-out `no-room` (checked in with Elvanto's No room) says "Checked in with no room, so there is nothing to check out."; the intake hold "Parent mobile needs fixing" points at the plan's Set mobile extra when the parent form has a valid number. The consent holds Two / Unsure / Unmatched keep their Elvanto wording. An older (rev 14) console never plans from a Tidy up link (consentLink); a rev-15 console plans a consentFix for each linked student (L2, Intake + Consents below).
- **Push tolerance:** an over-long pushed name/history is cut, not a 400 for the whole push. Contract fields stay optional, but the app serves only a console at rev 12 or later (X-1).
- `canEditGroupMembers` = admin, oversight, or I-am-leader of that group (lifegroup add/remove member, types `addGroupMember`/`removeGroupMember`).
- **Matching:** `autoMatch` keys on `matchFold` (first and last kept apart) and `genderFits`; every roster push re-runs it. Leaders: exactly one non-archived folded-name hit joins the roster as kind `leader` (`POST /sync/leaders`). **Elvanto gender wins (operator 2026-10-14):** a matched pair whose `matchFold` first + last and grade agree takes Elvanto's male/female (`genderFixes`); never writes blank, no write when equal, never logs names.
- **Matching screen says why (2026-10-21, L3):** Unmatched lists active Elvanto students (seen at services, groups or flows) with no free YS student of the same name. YS students come mostly from attendance imports, so a new youth is usually in Elvanto first (prod 2026-10-21: 84 Unmatched, none of them in `students` except 1 same-name student held by a duplicate Elvanto profile; 71 are in a flow, 14 in a lifegroup, which is why the operator "found them in YS"). No matching rule changed. Each tab has a one-line why (`_lkAdmMatchHtml`). A `none` row from `rosterForMatching` may carry `why` (a same-name YS student exists: later = free and gender fits, pairs at the next push/import; gender = `genderFits` refuses it; held = another roster row holds it) and `seenIn` (`flow`/`lifegroup`); with no candidate it reads "Not a YS student yet. YS shows them from Elvanto, in Flows." Manual student add/edit does not re-run `autoMatch`; the next roster push (about every 3 h) or import does.
- **Create / Create all on Unmatched (operator 2026-10-21, L3 r3/r4):** `POST /link/admin/create-students {personIds}` (admin; 1-25 ids, de-duplicated; the SPA sends batches of 10 so each call ends well inside the 20 s route limit, sums the counts, stops on the first error, and disables the buttons while it runs). It makes a YS student with the student create service (first, last, gender, grade; never a birthday; `dataSource` "Elvanto link") and links it with `setMatches` `manual` (the record a manual Match writes, so DNC/consent flow through). One eligibility rule in `matchRows` (`block`) drives both the list (`create` / `noCreate`) and the create, re-read right before each create: `none` and active, no candidate, no same-name YS student, the folded name once among active roster students, gender male/female (ruling: no gender = not eligible, never created as `other`; row says "No gender in Elvanto. Set it there, or use Match."), first and last name present, grade inside Setup. Reply `{created, skipped: {reason: n}}`. New students have zero attendance, so Student Connect and Health (`_hasAttended`) leave them out; check-in lists them from the roster as before. No migration. A single admin's timeout re-tap is guarded (disabled buttons, small batches, per-row re-check); **F1 (2026-10-22):** two admins at once make ONE student: each create first claims the person in `link_created_students` (migration 0042, person id primary key, insert on conflict do nothing; `claimCreate` / `settleCreate`); the loser is skipped as `notUnmatched`; a failed create releases its claim, and a claim with no student older than 5 minutes (a create that died) can be taken again; the row goes with its student (on delete cascade).
- **Hidden flow step:** step 0 by default (`modules.flowHiddenStep[flowId]`), hidden from non-admin logins only: `stepHidden(actor,row,picks)` returns false for `isAdminRole` (admin/oversight see and can complete it).
- **F4 (2026-10-22):** an Error log occurrence never folds into an **ignored** row (`and not ignored`); it starts a fresh row, so a new or recurring error shows again after Ignore. `src/tests/phone-scope-sweep.test.ts` calls every GET route (each `:param` with every student and leader id, plus the screens' queries) as juniorguys, grade8 and seniorgirls and fails on any out-of-scope or DNC phone; a new people route is swept automatically. The console now sends a Youth-Demographic person with no grade as `kind: 'student'` (was leader, which reconcile skips); grade/quad logins still cannot see a no-grade student (`canAccessGrade` needs a grade).

**Rules lifted from the 2026-10-16/17 rounds (still binding; full text in `docs/history/claude-md-archive.md`):**

Do not reintroduce a day's-service default (F-25 was a Claude phone-test suggestion, reversed; operator rulings are not flipped on test findings). - **Add-member tap guard (B24):** `_lkYpAdd` ignores taps for 400 ms after `_lkYpDraw` repaints (`p.drawn`) and 600 ms after an add (`p.at`). No confirm sheet, no swallowed-tap toast (operator rulings). "Students here (N)" excludes leaders (B09). Back on a dirty report draft asks first (B26). Non-admin refusal lines say "Tell the admin." (B10).
- **LG sort:** grade -> girls -> Mon-Sun -> name, no day last; `meetsWeekday()` in `link-rules.ts` (full day names; "Tues" is not a day, T-49).
- **Supersede:** `insertAction` with `supersede` cancels matching pending rows in the same transaction (`detail cancelled-by:<newId>`); intakeAnswer no longer sends a client `{kind:'cancel'}`; an older consentLookup of the same login + kind is cancelled. Without `supersede` the SQL is unchanged.
- **Stale pending:** link reads run `sweepIfDue()` (once per 5 min per instance; same too-old predicate as the claim). Pending over 15 min reads "Console hasn't picked this up yet (since ...)".
- **`lastRefused` / `fixKey`:** `GET /link/lifegroups` groups and `GET /link/flows` rows carry `lastRefused` = `{id,type,status:'refused',reason}` (absent when none; SPA shows a reason-only chip). `GET /link/actions` rows carry `fixKey` (admin only; consentFix personId, consentLink `cn:<subId>`) so the consent fix/link lines come back after the app was closed.
- `GET /link/intake` marks the view only with `view=1` (page entry, not background polls).
- **Duplicate vs stale:** `enqueueChecked`'s stale loop skips newer rows of the SAME type: a check-in a few seconds behind another leader's check-in answers `duplicate` (`mine: false`, their row); a newer opposite row is still stale (APP-16 B).
- `listActions` for a non-admin returns only `createdBy = actor` rows (pinned by `link.service.test.ts` "Plan F").
- **Door result poll:** `_lkCiPoll()` polls `GET /link/actions?ids=` for this login's own pending/claimed door rows (`_lkCiWaiting`): 5 s, 15 s once all are > 2 min old, a row dropped after 10 min, max 200 ids a call (operator ruling). Stops when none wait, off the door page, service change, hidden, or login swap; `_lkRefreshView` re-arms it on every door repaint. `sent`/`unclear`/`shadowed` apply in place via `_lkApply`; `refused`/`cancelled` trigger one `_lkLoadPeople`. The 60 s tick is unchanged; the poll never bumps `LINK.resGen`. Other phones see a tap on their next 60 s reload (`effectiveCheckState` counts ANY login's pending/claimed row).

Recency is in-memory `LINK.seenAt[svc][personId]` (`ponytail:` marked; upgrade = server first-seen stamp in `replaceMirror`). A typed name lists every match; "Nobody here by that name." only when nothing matches. Wake / return reloads the list (`_lkLoadPeople(svc, true)`).
