# Consent hub, DNC, flow steps

The admin intake screen is named "New youth & consent" everywhere (module `modules.intakeAdmin`, default Off). The More menu shows both "New person" (host) and "New youth & consent" (admin) on purpose.

- **Consent hub (2026-10-23):** replaces the old Intake + Consents tabs and Tidy up (module `modules.intakeAdmin` unchanged, default Off). Five stages; a Needs action list; the family page has Next step / More; intake rows carry `personId`/`family` (migration 0046); rows are kept 28 days; Flow steps step 0 and Parent Consent step 1 are read-only (`_lkHubOwned`); Bus > Forms. Data comes from the console's consent snapshot (`consentSnapshot`, 0045) with `consentLookup` as the fallback. After Save all / Text all the hub shows "Saving X of N…" (or "Sending X of N…") until the batch lands, then "Done" (2026-10-24, `I.hubSend`); no row finished for 3 min = "Still saving — check back later." and the 5 s poll stops (`stale`). Tests: `consent-hub.spa.test.ts`, `link-consent-snapshot.test.ts`, `bus-forms.spa.test.ts`.
- **DO NOT CONTACT (R1).** Roster and flow rows carry `consent: ok|contact|all|unknown` (`contact` = "contact with my child" opt-out, `all` = TOTAL non-consent date; migration 0027). DNC = contact|all (`isDnc`, `src/services/dnc.ts`). A student is DNC when its matched `link_roster` row is; an INACTIVE row still counts (**sticky**: a person dropped from a roster push keeps the last known flag, never gets phones back). Every student-shaped response gets `dnc: boolean`; for any login that is not admin/oversight `mobile` and `parentPhone` are `null` server-side (students, search, detail, My students summary, Home follow-up, at-risk list, Bus My car stops, `/connections/export`). Admin/oversight keep the numbers and get the red banner. Health and My students still list DNC students (marked red). `unknown`/unmatched shows the number. The strip's roster read is cached 60 s per instance. Tests: `dnc-strip.test.ts`, `flows-dnc.spa.test.ts`.
- **Flow steps (R4).** Admin/oversight only: remove from step (`removeFromFlowStep`, perm `link:flowRemove`, confirm + optional note posted to Elvanto notes; allowed on DNC rows), 4 persistent filter toggles (Junior/Senior x Guys/Girls, multi-select, all on, per device in localStorage; unknown grade/gender always shows), bulk Complete (ticks + ONE shared note, up to 50 `completeStep` items in one `/link/batch`; DNC rows cannot be ticked). DNC row: red banner, no number, no Text, Complete refused `LINK_DNC` (409). `LINK_BUSY_ROW` when a remove/complete is already open on the row. **`CONSENT_CHECK_FIRST` (409):** Complete on the New People consent step (step 0) is refused unless that person's consent row is done (or consent is `ok` with no not-done row), or (R4, LINK_REV 9) the student's consent Friday 9:00 (the first Friday after the flow row's `textedOn` when the console sent one (R8, rev 10), else after its `due`) has passed with no consent row and no consent on the profile: then the server sets `notReceived: true` on the stored payload and the console marks consent not received before it completes (`consentStepAllowed` -> 'done' | 'notReceived' | null). Before that Friday the row reads "Waiting (consent Fri …)", not Overdue (R6). The UI hides Complete while blocked and offers a Consents button.
- **Consent step = step 0 of this year's New People flow (E3, 2026-10-19):** `peopleFlowName` picks, among pushed flow names starting `Brisbane - Youth - New People <year>` (a prefix: a suffix still matches, so a renamed flow never switches the gate off; same-year tie = the shortest name), the highest year <= today's Brisbane year, else the highest (January before the new flow exists keeps last year's); same rule as the console's `youth-gather.js`. `isConsentStep` takes that name (no hardcoded 2026).

**Rules lifted from the 2026-10-16/17 rounds (full text in `docs/history/claude-md-archive.md`):**

- **textedOn (rev 10, migration 0037):** a flows push row may carry `textedOn` (stored in `link_flow_people.texted_on`); `consentFriday(due, textedOn)` counts from `textedOn` when set, else `due`.
- **Consents Other (rev 8, migration 0033):** `consentLookup` kind `other` (`CONSENT_LOOKUP_KINDS`), push rows `ConsentOtherRow {personId,rowId,name,date|null,source|null,why,link|null}`. `other` rows carry `flowId`, `stepId`, `dnc`, `consentFriday`, `notReceivedOk`, `marking` (`otherWait`). **Mark not received** only when `notReceivedOk`; **Mark all N** = one confirm (`_ikNrOpen`/`_ikNrGo`, `_ikPost` 20 a call), each a `completeStep` signed by "I am". The step-0 hand-off (`_lkStepConsents()`) searches First Last (current week, then at most 2 more GETs, else Other); an Other search with no match never blames the search (`_ikOtherMiss`).
- **Intake queue `ysc.ikq.<uid>`:** every intake POST is kept (`[{at, items}]`) BEFORE the keepalive fetch, removed once answered or on a 4xx; network/5xx/401 keep it. `_ikQFlush` resends kept items unchanged (same ids), oldest first, on intake load, `online`, `visibilitychange` and `_lkBoot`; over 24 h dropped with a toast; never throws or rejects. Flush re-reads the queue before each post; one kept item per slot (`_ikQSlot`, reuse only for the same payload via `_ikSame`); families in flight in `LINK.ikFam`. Logout (`_ikQLogout`): flush up to 5 s, then clear and return the drop count (doLogout shows one combined toast with the ID-check count, `_logoutLostText`); `LINK.ikStop` blocks late writes until the next login. Expired session: queue kept for that login (24 h) and resent on its next login; a different login (`_ikQLogin` in doLogin) clears other logins' `ysc.ikq.*`.
- Intake wording: plain past-tense result lines ("Made N changes"); sent answers say "Noted"; "Over 2 hours old. Tap Refresh."; linked-profile holds say approve or Unlink in Elvanto, then Refresh; `_ikNext` says "Fix in Elvanto, then Refresh:" when no hold is phone-answerable; `_ikCompareHtml` shows no display-only parent name/mobile cells; `_ikSubBar` is a native `<select class="fs ik-sub">`. ## Decline, Declined chip, Waiting, Refresh (rev 24, 2026-11-14)

- **Decline / Undo.** Every Needs-you or Ready row on the New youth & consent hub has a Decline button (the row the family opens: intake early, else consent). It sends an `intakeMark` (`_hubMarkRow`) and the row leaves the lists at once (`I.decl`, cleared when the console's push carries the same `declined` flag; reverted if the post is refused). Offline it is kept and resent like other saves (own queue slot per row).
- **Declined (n) chip** above the lists: shows only declined rows, each with Undo, no Save or Text. Declined rows are excluded from every other list, the Needs action count, the badge counts (`counts.declined` is apart) and Save all / Text all.
- **Needs action count (21 Nov, SW `ysc-v183`):** a "Parent texted late" hold counts as Waiting (grey, not counted) until its own Friday's cut-off (`_hubFriday`); after that it counts again. A Done child never counts, even with an old intake hold (e.g. a stale "Same person?").
- **Waiting grey.** A needs-you row whose reason starts "Waiting for replies until" (intake or consent) is a grey `waiting` reason, not a family that needs you.
- **Refresh** asks the console only for the dates in the week on screen (Current / Last; All = every week, one week at a time, newest first). The button reads "Updating…" and, with more than one week, "Updating… (week x of y)". F5 (2026-11-21): the ask stays open until every date it re-read (and, on a live snapshot, every lookup) is newer than the tap, polled every 5 s; then "Updated h:mm", or at 120 s "Console didn't answer" (the old lists stay).
- **Unclear name.** An unclear intake result's `name` is shown on the unclear card instead of "Unknown person".

## Consent automation (rev 25, 2026-11-21)
Spec: 11.1 `docs/superpowers/specs/2026-11-21-consent-automation-design.md`.
- **Prompts.** The console's 15-min `POST /sync/alerts` may carry `due` (`AlertsRequest`): `consentText` (Fri 19:45, that Friday's intake) and `consentRecord` (Fri 06:30, that Friday's consents), with counts. `consent-week-alert.ts` pushes counts only (never a name) to every active user with `notice:alerts` **and** `intake:admin`, leader picked or not; one claim per (kind, date) in `prompt_sends` (0058), at-most-once like `alert_sends`.
- **"This week" sheet** (`_cwOpen` / `_cwSheet` / `_cwRun`, screen `consentweek`, params `mode` intake|consent + `date`): counts for that date (to save, parents to text, to record, assume, move, held by hold type, unclear saves, rows near the clear-out). One **Run** is the confirm (R4): `_hubBulkOpen(kind, null, { date, auto: true })` skips its own modal. Intake: Save all, then Text all by itself once the saves land and the console re-pushes (`_cwNext` from `_hubLoad`; gives up at 10 min). Held rows never go (`_hubBulkRows` takes ready rows only).
- **Check and save again** (R3b): a rev 25 row may carry `stuck` (step keys the console saved before and Elvanto doesn't show now). `_ikStuckHtml` offers the button when every stuck step's action is in `IK_IDEMPOTENT` (= `IDEMPOTENT_ACTIONS` in `link-contract.ts` = the console's sent-log list); `complete`, `note`, `approveNew` show why not. The save carries `resend: true`; `checkIntakeItem` refuses it for a key not in `stuck` or an action not in the list. The console re-reads Elvanto first and sends once only if still missing.
- **Near the clear-out (F4):** the dates index (`GET /link/intake?mode=`) carries `nearPurge` (unprocessed rows dated 42+ days back; they go at 56). A purge that drops unprocessed rows logs `intake-purge-open` with a count only.
