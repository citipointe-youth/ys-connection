# Consent hub, DNC, flow steps

The admin intake screen is named "New youth & consent" everywhere (module `modules.intakeAdmin`, default Off). The More menu shows both "New person" (host) and "New youth & consent" (admin) on purpose.

- **Consent hub (2026-10-23):** replaces the old Intake + Consents tabs and Tidy up (module `modules.intakeAdmin` unchanged, default Off). Five stages; a Needs action list; the family page has Next step / More; intake rows carry `personId`/`family` (migration 0046); rows are kept 28 days; Flow steps step 0 and Parent Consent step 1 are read-only (`_lkHubOwned`); Bus > Forms. Data comes from the console's consent snapshot (`consentSnapshot`, 0045) with `consentLookup` as the fallback. After Save all / Text all the hub shows "Saving X of N…" (or "Sending X of N…") until the batch lands, then "Done" (2026-10-24, `I.hubSend`); no row finished for 3 min = "Still saving — check back later." and the 5 s poll stops (`stale`). Tests: `consent-hub.spa.test.ts`, `link-consent-snapshot.test.ts`, `bus-forms.spa.test.ts`.
- **DO NOT CONTACT (R1).** Roster and flow rows carry `consent: ok|contact|all|unknown` (`contact` = "contact with my child" opt-out, `all` = TOTAL non-consent date; migration 0027). DNC = contact|all (`isDnc`, `src/services/dnc.ts`). A student is DNC when its matched `link_roster` row is; an INACTIVE row still counts (**sticky**: a person dropped from a roster push keeps the last known flag, never gets phones back). Every student-shaped response gets `dnc: boolean`; for any login that is not admin/director `mobile` and `parentPhone` are `null` server-side (students, search, detail, My students summary, Home follow-up, at-risk list, Bus My car stops, `/connections/export`). Admin/director keep the numbers and get the red banner. Health and My students still list DNC students (marked red). `unknown`/unmatched shows the number. The strip's roster read is cached 60 s per instance. Tests: `dnc-strip.test.ts`, `flows-dnc.spa.test.ts`.
- **Flow steps (R4).** Admin/director only: remove from step (`removeFromFlowStep`, perm `link:flowRemove`, confirm + optional note posted to Elvanto notes; allowed on DNC rows), 4 persistent filter toggles (Junior/Senior x Guys/Girls, multi-select, all on, per device in localStorage; unknown grade/gender always shows), bulk Complete (ticks + ONE shared note, up to 50 `completeStep` items in one `/link/batch`; DNC rows cannot be ticked). DNC row: red banner, no number, no Text, Complete refused `LINK_DNC` (409). `LINK_BUSY_ROW` when a remove/complete is already open on the row. **`CONSENT_CHECK_FIRST` (409):** Complete on the New People consent step (step 0) is refused unless that person's consent row is done (or consent is `ok` with no not-done row), or (R4, LINK_REV 9) the student's consent Friday 9:00 (the first Friday after the flow row's `textedOn` when the console sent one (R8, rev 10), else after its `due`) has passed with no consent row and no consent on the profile: then the server sets `notReceived: true` on the stored payload and the console marks consent not received before it completes (`consentStepAllowed` -> 'done' | 'notReceived' | null). Before that Friday the row reads "Waiting (consent Fri …)", not Overdue (R6). The UI hides Complete while blocked and offers a Consents button.
- **Consent step = step 0 of this year's New People flow (E3, 2026-10-19):** `peopleFlowName` picks, among pushed flow names starting `Brisbane - Youth - New People <year>` (a prefix: a suffix still matches, so a renamed flow never switches the gate off; same-year tie = the shortest name), the highest year <= today's Brisbane year, else the highest (January before the new flow exists keeps last year's); same rule as the console's `youth-gather.js`. `isConsentStep` takes that name (no hardcoded 2026).

**Rules lifted from the 2026-10-16/17 rounds (full text in `docs/history/claude-md-archive.md`):**
- **notReceived (rev 9):** completeStep payload `notReceived: z.literal(true).optional()`, set only by the server (a phone-sent one is dropped; a replay compares without it). `GET /link/flows` rows carry `consentFriday` and `notReceivedOk`; the sheet and the bulk Complete sheet say what Complete records.
- **textedOn (rev 10, migration 0037):** a flows push row may carry `textedOn` (stored in `link_flow_people.texted_on`); `consentFriday(due, textedOn)` counts from `textedOn` when set, else `due`.
- **Consents Other (rev 8, migration 0033):** `consentLookup` kind `other` (`CONSENT_LOOKUP_KINDS`), push rows `ConsentOtherRow {personId,rowId,name,date|null,source|null,why,link|null}`. `other` rows carry `flowId`, `stepId`, `dnc`, `consentFriday`, `notReceivedOk`, `marking` (`otherWait`). **Mark not received** only when `notReceivedOk`; **Mark all N** = one confirm (`_ikNrOpen`/`_ikNrGo`, `_ikPost` 20 a call), each a `completeStep` signed by "I am". The step-0 hand-off (`_lkStepConsents()`) searches First Last (current week, then at most 2 more GETs, else Other); an Other search with no match never blames the search (`_ikOtherMiss`).
- **Intake queue `ysc.ikq.<uid>`:** every intake POST is kept (`[{at, items}]`) BEFORE the keepalive fetch, removed once answered or on a 4xx; network/5xx/401 keep it. `_ikQFlush` resends kept items unchanged (same ids), oldest first, on intake load, `online`, `visibilitychange` and `_lkBoot`; over 24 h dropped with a toast; never throws or rejects. Flush re-reads the queue before each post; one kept item per slot (`_ikQSlot`, reuse only for the same payload via `_ikSame`); families in flight in `LINK.ikFam`. Logout (`_ikQLogout`): flush up to 5 s, then clear and toast the drop count; `LINK.ikStop` blocks late writes until the next login. Expired session: queue kept for that login (24 h) and resent on its next login; a different login (`_ikQLogin` in doLogin) clears other logins' `ysc.ikq.*`.
- Intake wording: plain past-tense result lines ("Made N changes"); sent answers say "Noted"; "Over 2 hours old. Tap Refresh."; linked-profile holds say approve or Unlink in Elvanto, then Refresh; `_ikNext` says "Fix in Elvanto, then Refresh:" when no hold is phone-answerable; `_ikCompareHtml` shows no display-only parent name/mobile cells; `_ikSubBar` is a native `<select class="fs ik-sub">`. The intake hold wording (`IK_HOLD`, `_ikHoldText`, `_ikNext`) is a port of 11.1 `ix-logic.js` (keep in sync).
