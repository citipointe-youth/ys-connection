# Connection Audit, import, exports

Import screen rules and clearing import history: `src/api/CLAUDE.md`. Reconciliation after import: `docs/areas/error-log-reconcile.md`.

**Connection Audit module** is ported into the SPA as a delimited block (`/* ── CA MODULE … ── */`); remove = delete blocks + grep-delete `/*CA-HOOK*/` lines. The per-quad funnel is the integration ladder built from `D.students` (grade×gender cohorts). Since 2026-10-22 the screens are This week / Follow up / Term report plus the Data check page (`ca-week`, `ca-follow`, `ca-term`, `ca-quality`); the screen logic is top-level `ca*` functions inside the module markers, tested in `src/tests/ca-screens.spa.test.ts`.

- **Audits** are server-stored, year-keyed snapshots (`connection_audits`; v2 since 2026-10-22, v1 rows upgraded on read by `audit-upgrade.ts`). The console pushes five Elvanto sources after the Friday email (push kind `audit`, link rev 16); each (year, source) copy is the pushed cell table in `connection_audit_sources` (0043). `ingest()` parses (`audit-parse.ts`) and rebuilds the year (`audit-build.ts`, which reuses `attendance-build.ts`, `year-terms.ts`, `year-aggregates.ts`) under a per-year advisory lock. Admin manual upload: `POST /audits/sources/:source` (same ingest). The old 6-slot `POST /audits` is gone. error_log category `audit`, counts only.
- **Audit `get()` joins (ui22, 2026-10-22):** `get()` also reads flows + Consents rows and adds a server `consentPending` flag (reuses the app's consent rules; Follow up lists only consent-decided people; DNC counts as decided and lists as "Do not contact"); a missing phone is filled from the person's flow row (joined on personId only, before maskDnc).
- **Connection allocations** (admin only): Admin → New Year wizard (any time of year; the Data tab was removed 2026-10-22) exports/imports a student↔leader allocation CSV (`First Name,Last Name,Grade,Gender,Leader`, one pair per row, grouped by student). Import is name-matched and column-agnostic to grade/gender, syncs per student (students absent from the file are untouched), skips a student's removals if any of their leader names is unmatched, and returns a report of unmatched/ambiguous names. Logic lives in the pure `src/services/connection-allocations.ts`; `parseAllocationCSV` in the SPA preserves all columns (unlike attendance `parseCSV`).
- **Connect Setup export** (`exportConnectCSV()`, all roles — own-gender-only for grade/quad): `GET /connections/export` now returns structured rows (`ConnectionService.exportCsv` / `ExportRow`, not a CSV string); the SPA builds an **.xlsx** workbook client-side via the same vendored SheetJS build used to read Excel imports (`_ensureXlsx()`), lazy-loaded on click. One row per leader (name/grade/gender only) followed by that leader's connected students (their own grade/gender — not the leader's — plus Health/Youth %/Lifegroup %/DOB/ Mobile/Parent Mobile), grouping relies on the rows already being sorted leader-then-student. **Independent of** the admin-only allocations export/import above — separate route, service method (`exportCsv` vs `exportAllocations`), and frontend function (`exportConnectCSV()` vs `exportAllocationsCSV()`); changing one doesn't affect the other.
- **Elvanto export guide** (`openExportGuide('import'|'audit')`, `EXPORT_GUIDES()` + `_egGuide(key)`): screenshot walkthroughs in `public/img/export-help/*.png`; in **Term 1** the user must set a Custom range starting from last year's Term 4; images are cache-first, so bump the SW cache if an image is replaced.
