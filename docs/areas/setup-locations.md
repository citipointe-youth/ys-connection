# Setup, ministryConfig, other locations

- `ministryConfig` (`src/core/ministry-config.ts`, `MinistryConfigSchema` + `MINISTRY_CONFIG_DEFAULTS`) is the single source of truth every repo and the SPA read from for per-deployment configuration (branding, labels, structure, roles, modules). Stored as `app_settings.ministry_config` jsonb; `PATCH /settings` deep-merges via `mergeMinistryConfig`. UI copy goes through `L(key)` labels; features through `modules.*` toggles. Setup presets (kept by ruling D3, 2026-10-19): a preset tap asks first, then sets only the fields some preset defines (cohort model, gender rule, Director/Quad, Connection Audit, Lifegroups, Export guides) from `MINISTRY_CONFIG_DEFAULTS` + that preset, so presets never pile up; every other field (link modules, intake, Bus, branding, labels, logins) is kept (CY-D1, `r19-preset-guard.spa.test.ts`). Status/quad colours are deliberately NOT configurable (categorical, not brand).

Spec `docs/superpowers/specs/2026-10-10-multi-location-rollout-design.md`. Other locations run their own fork + Supabase + Vercel + Google project; guides are `docs/DEPLOYING.md` and `docs/GOOGLE-SETUP.md` (ASD-STE100; `node scripts/check-guide-style.js` checks them).
