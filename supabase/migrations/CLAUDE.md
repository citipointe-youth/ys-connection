# Migrations (supabase/migrations)

`supabase/migrations/` holds **`0001`–`0051`** (4-digit; was `0001`–`0008` right after the r19 fold): `0001_baseline_schema.sql` is the full end-state, then `0002_rls`, `0003_seed_accounts`, `0004_backfill_grade_gender`, and the four prayer migrations `0005`–`0008`. The original **`001`–`020`** (3-digit) were folded into `0001` and the archive folder was deleted in r19 (git history keeps the files).

**So: any 3-digit migration number cited in docs/HISTORY.md (e.g. "migration `013`", "`018_ministry_config`") refers to a folded-in (deleted) file, not something you will find in `supabase/migrations/`.** Its effect is folded into `0001_baseline_schema.sql`. Don't go looking for it, and don't renumber a new migration to match one — the next migration is `0052`. Recent: `0027` consent, `0028` notices, `0029` notice push subscriptions, `0030` console progress, `0031`/`0033` CHECK widenings, `0032` `newperson_requests`, `0034` `bus_run_vehicles.locked` (the 2026-10-17 bus lock), `0035` error_log tier + `reconcile` category, `0036` `reconcile_runs`, `0037` `link_flow_people.texted_on` (R8), `0038` bus charter, `0039` `link_flow_people.service_visits` (rev 13), `0040` per-location Elvanto in `ministryConfig.elvanto` (multisite R1, ysc-v135), `0041` outbox type `recheck` (L7, rev 15, ysc-v138), `0042` `link_created_students` (F1 2026-10-22, the Create claim), `0043` `connection_audit_sources` (Connection Audit, rev 16, ysc-v140), `0044` bus consent forms (outbox type `busConsentCheck`, `bus_consent_forms` + `bus_consent_submits`, drops `bus_consents`, Brisbane form ids; rev 18, ysc-v143), `0047` `lifegroups.quad` (2026-10-24, lg/junior-senior-groups: a "Junior/Senior Girls/Guys" group with no Grade N keeps grade null and records its quad; `groupQuadOf` in enums.ts; visible to that quad's login and to a grade login holding a grade in its bracket, same gender (`canAccessQuadGroup`); not listed under per-grade stats rows). `0048` `students.graduated_at` (r25 2026-10-25: a roster push that sees a matched Year 12's Elvanto grade go 12 -> blank stamps it; `IStudentRepository.findAll()` leaves graduated students out, `findAllWithGraduated()` is for imports and roster matching; admin Student Search > Graduated (N) > Undo = `POST /students/:id/ungraduate`). `0049` outbox type `doorSearch` (rev 20, the door's Elvanto search; type CHECK only). `0050` `module_switchboard`, `0051` `dashboard_birthdays` (see the files). Check with `ls supabase/migrations/*.sql | tail -1`.

**Migrations now apply automatically in the Vercel production build** (`scripts/migrate.ts`, `npm run migrate`, `vercel-build`): it records versions in `schema_migrations`, baselines `<= 0014` once for a database that already has `users` + `bus_run_edits` (Citipointe), holds an advisory lock, and prints `Database up to date — N of N changes applied (K new).` Rules: files stay additive (two shipped exceptions: `0026` dropped `bus_leader_prefs.fixed_vehicle_id`, and before rolling back below bus/remove-fixed-leaders (43e253b) run `alter table bus_leader_prefs add column if not exists fixed_vehicle_id uuid;`; `0044` dropped `bus_consents`, see DEPLOY.md); no `create index concurrently`; never edit a shipped file (`0003` was the one exception, now an empty comment); bump `LATEST_MIGRATION` in `src/core/schema-version.ts` with every new file (a test enforces it).
